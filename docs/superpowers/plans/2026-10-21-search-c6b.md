# Slice C6b, search and on-this-day — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET /bonds/{bondId}/search?q=` finds the days of the caller's archive on which an
entry they can read in full holds every word of `q` (accents and case folded), and
`GET /bonds/{bondId}/on-this-day` gives the days of the same calendar date in earlier years;
both in the archive's day shape, through the archive's gate.

**Architecture:** V25 fills `entries.text_search` for live rows, adds
`search_vector tsvector GENERATED ALWAYS AS (to_tsvector('simple',
public.immutable_unaccent(coalesce(text_search, '')))) STORED` and a GIN index. The
application writes `text_search` in one place (`EntryStore`, from the entry's text), so every
erasure, which goes through `EntryStore.update` with the text gone, empties it. Search is the
archive's reading with a different candidate query: `ArchiveDays.matching` lists days whose
**matching row** is one SQL believes the caller may read in full, returns which entries
matched, and `GetDays` reads the days through the gate, marker last, keeping a day only if a
matched entry was read in full. The windowed fill that makes `favourites=true` indistinguishable
from a hand deletion (ADR-0036 decision 7) is factored out of `GetDays.page` and shared.
On-this-day is a one-statement read of the same kind, empty on a bond that takes no writes.

**Tech Stack:** Kotlin, Spring Boot 4.1, Jackson 3 (`tools.jackson`), Postgres 18
(Testcontainers `postgres:18`, which ships `unaccent` and `btree_gin`, both `trusted`: run on
2026-10-21), `JdbcTemplate`, Flyway, Konsist, Kotest matchers, JUnit 5.

**Spec:** `docs/superpowers/specs/2026-09-28-the-daily-loop-design.md` §5.2 (the two C6 rows),

## The rulings this plan implements

**The owner's (Daniel, 2026-10-21, asked directly):**

- **Q-S2.** Search uses the archive's predicate (`ArchiveDays.SEEN`): the caller's own
  unrevealed entries are found; the partner's only once revealed.
- **Q-S4.** Whole words, accents fold (`unaccent`; the `'simple'` configuration, no stemming,
  no prefix).
- **Q-O3.** On-this-day answers empty on an ended bond, left or blocked alike, byte-identical.
- **Q-O2.** Opt-in gates only the weekly push (Phase 4). The endpoint always answers; C6b
  builds no setting.

**The controller's defaults (2026-10-21; each "the owner's to turn" in ADR-0039):**

1. Q-S1: no server snippet or highlight (H-S8); a client may highlight.
2. Q-S3 / S2: results are days in the archive's shape, newest first, keyset on the date with
   the archive's cursor; no count or total (H-S3); byte-bounded pages.
3. Q-S5: search reads on an ended bond and for the member who left, as the archive does.
4. Q-O1: every prior year with a listed day on that bond-local date, newest first;
   unpaginated, byte-bounded.
5. Q-O4: days whose visible entries are all tombstones are not resurfaced (excluded in SQL);
   solo days follow `SEEN`.
6. Q-O5: placement is a design gap (no frame); recorded in `states.md` and spec §11.
7. 29 February shows only on 29 February. "Today" is the bond-local date (BR-3).
8. S5/S6: follow doc 07. The application writes `text_search` (on submit and on a pre-reveal
   `PATCH`); `search_vector` is generated from `text_search`; GIN index; every erasure nulls
   `text_search`; V25 backfills live rows. S7: measure `EXPLAIN` on a seeded large dataset and
   switch to `btree_gin (bond_id, search_vector)` if the plan scales with the table.
9. T-11: `plainto_tsquery` (or `websearch_to_tsquery`), never raw; `q` bounded (1–100
   graphemes, blank `422`, never echoed); `q` never in logs or traces (`SecretsNeverLoggedTest`
   joins).
10. `Cache-Control: private, no-store` on both; both routes get cross-tenant fixtures.

## Decisions this plan makes (each goes into ADR-0039, apart from the rulings)

1. **Search is the archive's reading with another candidate query.** `GetDays.page`'s loop
   (candidates in windows, the gate after each window's entries, the marker read last, a day
   dropped by the gate leaving no trace, the byte bound, the look-ahead at the bound) is
   factored into one private `fill` that both `page` and `search` call. *Reason:* ADR-0036
   decision 7 shows what a second copy of that loop costs: the first version of the
   favourites feed told a withdrawal from a deletion by hand through an empty page with a
   cursor. One loop, one proof (`WithdrawalTwinArchiveTest`, and its twin for search here).
2. **The match and the visibility are asked of the same row** (H-S2). `ArchiveDays.matching`
   joins `entries` to `bond_days` and requires, of each matching entry row: its vector
   matches, `SEEN_ROW` (the caller wrote it or it was revealed), and its author is not among
   the known withdrawn (H-S1, before `LIMIT`). It returns each day with the ids of its
   matching entries. An erased row is not asked about: its projection is `NULL` and its
   vector empty (decision 5), so it cannot match; a clause that restated that would be a
   guard no test could see removed. *Reason:* "a day with any `SEEN` entry and any matching
   entry" lists a day because a `LOCKED` entry matched, which says what the partner wrote
   before the reveal. **Two guards hold H-S2 and H-S1** (this SQL, and decision 3's filter
   after the gate). Each one's removal is invisible while the other stands, except where the
   SQL decides what `LIMIT` cuts: over a history longer than the fill reads in one request
   (about 1,000 days), a filter applied only after the gate leaves an empty page with a
   cursor. Each guard has a test that sees it go (Task 2, Steps 4, 7 and 10).
3. **After the gate, a day is shown only if a matching entry was read in full.** The SQL is a
   filter (ADR-0036 decision 2). A withdrawal that commits between the candidate query and
   the marker read makes a matched entry a tombstone; that day is then dropped and the fill
   reads on, exactly as `favourites=true` does. *Reason:* the gate, not the SQL, decides
   what is shown, and decision 1's loop makes a dropped day invisible.
4. **A shown day is the whole day**: both entries, each rendered through the gate, the other
   entry possibly a tombstone or `LOCKED`. Nothing says which entry matched. *Reason:* S2 and
   the controller's default 1 (no snippet, no highlight); the screen draws day cards.
5. **`text_search` is written by `EntryStore`, from the entry's text, and nowhere else.**
   `searchProjectionOf(text: EntryText?): String?` in `infra/database` is the one rule
   (today: the text as stored). `Entry.toEntity` and `EntryStore.update` both call it. The
   domain `Entry` does not carry it. *Reason:* every write of an entry goes through
   `EntryStore.insert` or `EntryStore.update` (read on 2026-10-21: `SubmitEntry.kt:484`,
   `ChangeEntry.kt:121`, `EraseEntry.kt:104`, `RevealDay.kt:43`, `CloseDay.kt:178`), and
   every erasure, by the author, by the withdrawal consumer, by the close job's pre-step,
   goes through `EraseEntry`, which writes `text = null`. So the column empties with the
   words by construction (S6), and Phase 5 changes one function.
6. **`search_vector` is generated from `text_search` through an `IMMUTABLE` wrapper.**
   `unaccent(text)` and `unaccent(regdictionary, text)` are both `STABLE` (run on 2026-10-21:
   `provolatile = 's'`), and a generated column takes only immutable expressions. V25 creates
   `public.immutable_unaccent(text)` as `LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT RETURN
   public.unaccent('public.unaccent'::regdictionary, $1)`: the dictionary named, the schema
   named, the SQL-standard body (parsed at creation, so its dependency on the extension is
   recorded). *Reason:* the common wrapper. *Cost:* the promise of immutability is ours.
   If a Postgres upgrade changes `unaccent.rules`, stored vectors are folded the old way
   until the column is regenerated (`UPDATE entries SET text_search = text_search`).
   Recorded in "Revisit when".
7. **The query folds `q` with the same function**:
   `e.search_vector @@ plainto_tsquery('simple', public.immutable_unaccent(?))`, `q` bound as
   a parameter (T-11). `plainto_tsquery`, not `websearch_to_tsquery`: every word must appear
   (AND) **in one entry**: words split between the day's two entries do not find it, because
   the match is asked of each row. No operator syntax is offered that the owner did not rule
   on. *Run on
   2026-10-21 in a throwaway `postgres:18`, as a non-superuser:* `cafe` and `CAFÉ` find
   "café", `acao` finds "Ação", `caf` finds nothing, the ligature `ﬁne` finds "fine",
   Cyrillic and CJK tokens are indexed as words, and an emoji is no lexeme at all.
8. **A `q` with no lexeme** (only punctuation, only emoji) is `200` with `{"items":[],
   "nextCursor":null}`, not `422`. Postgres emits the notice "text-search query contains only
   stop words or doesn't contain lexemes, ignored", which carries no part of `q` (run on
   2026-10-21). *Reason:* it is a well-formed request that matches nothing; refusing it would
   need a second tokeniser in Kotlin to restate Postgres's.
9. **`q` is required, and is 1 to 100 graphemes, at most 1,024 UTF-8 octets, with no
   U+0000.** Graphemes are counted on the NFKC-normalised, trimmed form, as an entry's are
   (FR-041's convention); blank is Kotlin's `isBlank` on that form (a lone non-breaking space
   is blank). The octet cap is this plan's: a grapheme has no upper bound on its length, and
   `q` travels in a URL. One `422 VALIDATION_FAILED` per problem, field `q`, codes `REQUIRED`
   and `VALID_SEARCH`; never the value. Read after the guard. U+0000 is refused because
   Postgres `text` cannot hold it (a `500` otherwise). *Cost:* 41 ZWJ family emoji are 100
   graphemes and 1,025 octets, refused.
10. **The grapheme count moves to `domain/Graphemes.kt`**, shared by `EntryText` and
    `SearchTerms`. *Reason:* a rule in one place; `EntryTextTest` holds it unchanged.
11. **`q` sent twice is read as Spring binds it**, the two values joined by a comma, so both
    words are searched for. Accepted: it is the caller's own request, harmless, and `limit`
    sent twice is already refused by its own reading.
12. **The search page is `DaysResponse`**, `{items, nextCursor}`: the feed's own type, so
    the contract has one page shape. The cursor is `DayCursor` and limit 1–50, default 20,
    parsed by `DaysQuery` (one reading of both).
13. **On-this-day is `{items: [day…]}`** (`OnThisDayResponse`): days dated the same month
    and day as the bond-local today in an earlier year, newest first; at most
    `ON_THIS_DAY_YEARS = 100` candidates; filled by the archive's `Filling` under the same
    192 KiB text bound, the first day always taken. Days past the bound are left out with no
    cursor. *Reason:* the controller's default 4 (unpaginated, byte-bounded). *Cost:* a bond
    with three or more years of the largest possible entries on one date loses the oldest
    from this route (still in `/days`). Realistic entries are a few hundred octets.
14. **On-this-day is empty whenever the bond takes no writes from the caller**
    (`!membership.takesWrites`, C6a's predicate: ended, left, blocked, counting down to
    deletion), decided before anything is read, so the bytes are the same for every cause.
    *Reason:* Q-O3, extended to the deletion countdown (`PENDING_DELETION`, `isOpen` false)
    because the C6a prompt already treats it so, and a cancelled countdown brings the
    memories back.
15. **On-this-day lists a day only if it holds an entry SQL believes the caller may read in
    full** (`SEEN_ROW` and `LIVE_ROW` and not withdrawn), and after the gate only if one was
    read in full. A day of tombstones is not resurfaced (Q-O4, H-O5); the partner's tombstone
    beside a live entry is shown as the gate renders it.
16. **"Today" is `DayAssignment.dateFor(clock.instant(), null, membership.anchorTimeline
    .asCalendar()) { false }`**, `GetToday`'s own call (BR-3, H-O6). Today itself is excluded
    (`d.date < today`). The match is `EXTRACT(MONTH)` and `EXTRACT(DAY)`, so 29 February
    matches only 29 February, and 28 February in a leap year shows only earlier 28
    Februaries.
17. **Both routes keep the API's default `Cache-Control`**, `no-cache, no-store, max-age=0,
    must-revalidate` with `Pragma: no-cache` and `Expires: 0` (Spring Security's writer adds
    it to any response that sets none; `CacheHeadersTest` holds it). The controller's default
    10 says `private, no-store`. The default already forbids every cache from storing the
    response, which is what `private, no-store` is for; writing `private, no-store` by hand
    would drop `Pragma` and `Expires` and make these routes a second exception in
    `CacheHeadersTest` beside the archive. *This is a deviation from the letter of the
    controller's default, for the controller to confirm or turn* (cost of turning: one header
    line per route and a third case in `CacheHeadersTest`).
18. **No `ETag`, no conditional read** on either route. `no-store` makes a validator useless,
    and an `ETag` header is one more place a digest of somebody's words could reach a log.
19. **No rate bucket of their own.** Both sit under the global per-user 120 a minute, as the
    archive does (ADR-0036 decision 16). A search costs an index lookup bounded by the bond
    (Task 2 Step 13 measures it). *Alternative:* a `SEARCH_USER` bucket; it costs an ADR-0023
    amendment, a smoke probe driven to `429`, and a client that searches as the user types
    being refused.
20. **Both routes run the joining-day reconcile** (`ReconcileJoiningDay.beforeRead`) after the
    guard and the parameters, as the archive does (spec §12.4).
21. **The guard is one function for the new controllers**, `BondAccess.guard(caller, bondId)`
    in `web/BondGuard.kt` (text id, the one `404` for a value that is not a UUID). The older
    copies in `DaysController`, `EntriesController` and `StreakController` are left: state-map
    `codeRef`s quote them. Owed.
22. **The query string is held to the entry's standard in the logs.** `SecretsNeverLoggedTest`
    searches for a watched word; every logger it names as printing `q` is pinned at `INFO` in
    `application.yml` (predicted: Spring Security's `FilterChainProxy`, which prints the request
    line with its query at `DEBUG`; to be confirmed by running).
23. **CLAUDE.md's "never … a second column" is amended** (and AGENTS.md's copy, word for
    word): `entries.text_search` and the vector generated from it are the one sanctioned copy
    of an entry's words, kept for search, emptied by every erasure (ADR-0039). *Reason:* the
    controller's default 8 creates exactly the copy the rule forbids, and CLAUDE.md says the
    document wins and the file is the bug.
24. **`scripts/moyi` gives curl the URL in a config file** (`-K`), for every command, so a
    search's `q` is never an argument of a process (the script's own rule).
25. **`search` reads on an ended bond and for a member who has left** (the controller's
    default 3): no `takesWrites` check, as `GetDays.page` has none.

## Review focus

The five failure modes most likely to reach a person, each pinned by a test in the task that
owns the code:

1. **The partner's unrevealed words find a day.** A word only in the partner's entry of
   today, or of a past day that never revealed, lists that day for the caller, or changes
   the page (its length, its cursor). Must not, by the same row predicate, in every page
   size. (Task 2, Steps 4 and 7.)
2. **A withdrawal shows through search before the erasure.** An author who blocked with
   withdrawal, the consumer not yet run: a page empty with a cursor, or a shorter page, that
   a hand deletion would never give, including a history longer than the fill's 1,000-day
   bound. (Task 2, Step 10.)
3. **What people type into a search box.** Accents and case (`Café`, `CAFE`, `cafe`), a word
   inside another (`caf`), two words in either order, punctuation or emoji only, a lone
   non-breaking space, U+0000, 101 characters, 41 family emoji: a match by folding, an empty
   `200`, or one `422` naming `q` without echoing it. Never a `500`. (Task 2, Steps 1 and 4.)
4. **Words that should be gone are still findable.** After a delete, a withdrawal's erasure,
   or a pre-reveal edit that replaced a word: the old word finds nothing and the row's
   `text_search` is `NULL` (erased) or the new words (edited). (Task 1, Steps 2 and 5;
   Task 2, Step 4.)
5. **The wrong "today".** Just after the bond's midnight but before UTC's, on 29 February, on
   28 February of a leap year: on-this-day shows the bond-local date's earlier years and no
   other date. (Task 3, Steps 1 and 3.)

```sql
-- Slice C6b: full-text search over entries (FR-050, FR-091, ADR-0039).
--
-- What is searched is entries.text_search (V12), not entries.text. Doc 07 §2 keeps the two
-- apart for Phase 5 (D-13): when text becomes ciphertext, text_search becomes a lossy
-- projection and search keeps working against it, "an acknowledged partial disclosure"
-- (doc 09). Until then the projection is the text itself, written by the application
-- (`searchProjectionOf`, in EntryStore) on submit and on an edit before the reveal, and
-- emptied by every erasure, which goes through EntryStore.update with the words gone
-- (ADR-0039 decision 5). It is the one copy of an entry's words outside entries.text that
-- this codebase keeps (CLAUDE.md, amended with this slice).
--
-- search_vector is Postgres's, generated from the projection and never written by anybody.
-- 'simple', not 'english': entries are multilingual, and 'simple' neither stems nor drops
-- stopwords, so a search is for whole words as written (the owner's Q-S4). Accents and case
-- fold: "cafe" finds "Café".
--
-- unaccent is STABLE, in both its forms, and a generated column takes only IMMUTABLE
-- expressions. immutable_unaccent is the usual wrapper: the dictionary named, the schema
-- named, and a SQL-standard body, parsed now, so its dependency on the extension is
-- recorded. The promise of immutability is ours: if an upgrade of Postgres changes
-- unaccent.rules, stored vectors keep the old folding until they are regenerated
-- (UPDATE entries SET text_search = text_search). The search's query folds its words with
-- this same function, so the two sides cannot fold differently.
--
-- The backfill fills the projection of every live row, before the column is added, so the
-- table is rewritten once. An erased row keeps NULL: its words are gone (BR-10). Both marks
-- of an erasure are asked, as Entry.isErased asks them.
--
-- entries_search_idx: GIN on the vector. Whether a query on one bond's entries reads in
-- proportion to that bond or to the table (NFR-033) was measured on this branch; ADR-0039
-- has the numbers and says whether this became btree_gin (bond_id, search_vector).
CREATE EXTENSION IF NOT EXISTS unaccent SCHEMA public;

CREATE FUNCTION public.immutable_unaccent(text) RETURNS text
    LANGUAGE sql IMMUTABLE PARALLEL SAFE STRICT
    RETURN public.unaccent('public.unaccent'::regdictionary, $1);

UPDATE entries
SET text_search = text
WHERE text IS NOT NULL AND deleted_at IS NULL AND status <> 'DELETED';

ALTER TABLE entries
    ADD COLUMN search_vector tsvector
        GENERATED ALWAYS AS (to_tsvector('simple', public.immutable_unaccent(coalesce(text_search, '')))) STORED;

CREATE INDEX entries_search_idx ON entries USING gin (search_vector);
```

```kotlin
package com.moyi.gratitude.domain

import java.text.BreakIterator
import java.util.Locale

/**
 * User-perceived characters, per Unicode text segmentation
 * ([UAX #29](https://unicode.org/reports/tr29/)) rather than `String.length`'s UTF-16 code
 * units: a ZWJ emoji sequence is one of these and several of those. What "characters" means
 * wherever this module limits a person's text: an entry ([EntryText]) and a search
 * ([SearchTerms]). One count, so the two cannot come to disagree.
 */
internal object Graphemes {
    fun count(text: String): Int {
        val boundary = BreakIterator.getCharacterInstance(Locale.ROOT)
        boundary.setText(text)
        var count = 0
        while (boundary.next() != BreakIterator.DONE) count++
        return count
    }
}
```

```kotlin
package com.moyi.gratitude.domain

import java.text.Normalizer

/**
 * What a member searched for (`q`, ADR-0039 decision 9), checked once at the edge.
 *
 * **Kept as sent.** Postgres folds case and accents on both sides of the match with one
 * function (`public.immutable_unaccent`, V25); nothing here normalises what is searched for,
 * as nothing normalises what was written ([EntryText]). NFKC and `trim` are used only to
 * **decide**, on a copy, exactly as an entry's limits are decided.
 *
 * - **No U+0000**: Postgres `text` cannot hold it, and the statement would fail as a `500`.
 * - **At most [MAX_OCTETS] UTF-8 octets**, on the raw text: a character has no upper bound on
 *   its length, and `q` travels in a URL.
 * - **Not blank** and **at most [MAX_GRAPHEMES] characters**, on the NFKC form trimmed, by
 *   [Graphemes.count]: FR-041's convention for an entry, so a client counts both one way.
 *
 * **Redacted.** What somebody looks for in what two people wrote is their words (T-19); it
 * reaches no log, no exception message and no `toString`.
 */
@JvmInline
internal value class SearchTerms private constructor(
    val value: String,
) {
    override fun toString(): String = "SearchTerms(redacted)"

    companion object {
        const val MAX_GRAPHEMES = 100
        const val MAX_OCTETS = 1024
        private const val NUL = '\u0000'

        /** [raw] as a search, or `null` when it cannot be one. Which limit it crossed is not said: the answer is one `422`. */
        fun of(raw: String): SearchTerms? {
            if (NUL in raw || raw.toByteArray(Charsets.UTF_8).size > MAX_OCTETS) return null
            val counted = Normalizer.normalize(raw, Normalizer.Form.NFKC).trim()
            if (counted.isBlank() || Graphemes.count(counted) > MAX_GRAPHEMES) return null
            return SearchTerms(raw)
        }
    }
}
```

```kotlin
    @Transactional(readOnly = true)
    fun page(
        membership: BondMembership,
        before: LocalDate?,
        until: LocalDate?,
        limit: Int,
        favouritesOnly: Boolean,
        textOctets: Int = PAGE_TEXT_OCTETS,
    ): DaysPage {
        require(limit in 1..MAX_LIMIT) { "a page of the archive is 1 to $MAX_LIMIT days" }
        return fill(
            membership,
            before,
            limit,
            textOctets,
            select = { from, size -> candidates(membership, from, until, favouritesOnly, size) },
            // With favourites only, a day on which nothing marked can be read any more is passed over.
            shows = { _, kept -> !favouritesOnly || kept.isNotEmpty() },
        )

    /**
     * `GET /bonds/{bondId}/search` (FR-050, FR-091; ADR-0039): the days of the archive on which
     * one entry the caller can read in full holds every word of [terms], a page at a time.
     *
     * **[page]'s reading with another query.** The candidates are [ArchiveDays.matching]'s,
     * which excludes the known withdrawn before its `LIMIT`, asked afresh for every window
     * as the favourites feed asks. Every day is read through the gate, the marker last, and
     * **shown only if an entry that matched was read in full**: a withdrawal that commits
     * after the candidates were read makes that entry a tombstone, and the day is passed over
     * as `favourites=true` passes one over, leaving no trace in the page or its cursor
     * (ADR-0036 decision 7). A shown day is the whole day: both entries as the gate renders
     * them, and nothing to say which matched.
     *
     * **No `hasLeft` or `isOpen` check**: an ended bond is its archive, and is searched as it
     * is read (the controller's default 3).
     *
     * @throws IllegalArgumentException [limit] is outside 1..[MAX_LIMIT], as for [page].
     */
    @Transactional(readOnly = true)
    fun search(
        membership: BondMembership,
        terms: SearchTerms,
        before: LocalDate?,
        limit: Int,
        textOctets: Int = PAGE_TEXT_OCTETS,
    ): DaysPage {
        require(limit in 1..MAX_LIMIT) { "a page of the archive is 1 to $MAX_LIMIT days" }
        return fill(
            membership,
            before,
            limit,
            textOctets,
            select = { from, size ->
                // Asked again for every window: see `candidates`.
                val withdrawn = access.readerNow(membership).withdrawnAuthors
                archive.matching(membership.bondId, membership.memberId, terms, from, size, withdrawn)
            },
            shows = { day, _ -> day.matchedInFull },
        )
    }

    /**
     * The reading [page] and [search] share, which [page]'s KDoc describes: candidates from
     * [select] in windows, each window's entries read through the gate with the marker read
     * after them, the days [shows] keeps offered in order to a [Filling], and the look-ahead
     * at the bound. [select] is asked for the days strictly before its date (none: from the
     * newest), at most its count. [shows] is given each day after the gate and the caller's
     * own marks among what it read in full.
     */
    @Suppress("LongParameterList") // Each a separate fact of the reading.
    private fun fill(
        membership: BondMembership,
        before: LocalDate?,
        limit: Int,
        textOctets: Int,
        select: (LocalDate?, Int) -> List<ArchiveDay>,
        shows: (Read, Set<EntryId>) -> Boolean,
    ): DaysPage {
        val page = Filling(limit, textOctets)
        var examined = before
        var older = true
        var windows = 0
        while (older && !page.more && windows < MAX_WINDOWS) {
            // The first window is one more than the page: that day's presence is how "there is more" is known.
            // `addExact`, though `limit` is at most MAX_LIMIT by the callers' checks: a sum that cannot wrap, whoever calls.
            val size = if (windows == 0) Math.addExact(limit, 1) else REFILL_WINDOW
            val candidates = select(examined, size)
            val read = read(membership, candidates)
            val marked = marksOf(membership, read)
            val reacted = reactionsOn(read)
            for (day in read) {
                val kept = day.keptOf(marked)
                if (shows(day, kept)) page.offer(day, kept, reacted)
            }
            windows++
            older = candidates.size == size
            examined = candidates.lastOrNull()?.date ?: examined
        }
        val next =
            when {
                page.more -> page.days.last().date

                // The bound was reached and the last window came back full. Full is not the same as "there is
                // more": the archive may end exactly there, and a cursor would then promise a page that does
                // not exist. So look once more, for one day, before giving it; then go on from the last day
                // examined, shown or not.
                older -> examined.takeIf { select(it, 1).isNotEmpty() }

                else -> null
            }
        return DaysPage(page.days, next)
    }
```

```kotlin
/**
 * The three query parameters of `GET /bonds/{bondId}/search`, read after the guard, as
 * [DaysQuery] reads the feed's and for its reasons: a stranger is told the bond's `404` before
 * anything about `q`, and a refusal is this application's `422`, naming each parameter and
 * never its value.
 *
 * `limit` and `cursor` are [DaysQuery]'s own reading (one reading of each, wherever they are
 * taken). `q` is [SearchTerms.of]'s. Every problem is reported at once.
 */
internal data class SearchQuery(
    val terms: SearchTerms,
    val limit: Int,
    /** From the cursor: days strictly before this date. */
    val before: LocalDate?,
) {
    companion object {
        /** @throws DaysQueryNotValidException naming each parameter that is missing or cannot be read. */
        fun parse(
            q: String?,
            limit: String?,
            cursor: String?,
        ): SearchQuery {
            val violations = mutableListOf<FieldViolation>()
            val paging =
                try {
                    DaysQuery.parse(limit = limit, cursor = cursor, until = null, favourites = null)
                } catch (refused: DaysQueryNotValidException) {
                    violations += refused.errors.orEmpty()
                    null
                }
            val terms =
                when (q) {
                    null -> null.also { violations += Q_MISSING }
                    else -> SearchTerms.of(q) ?: null.also { violations += Q_NOT_SEARCHABLE }
                }
            if (paging == null || terms == null) throw DaysQueryNotValidException(violations)
            return SearchQuery(terms, paging.limit, paging.before)
        }

        // About the parameter, never its value: what somebody searched for is their words.
        private val Q_MISSING = FieldViolation("q", "REQUIRED", "is required: the words to look for")
        private val Q_NOT_SEARCHABLE =
            FieldViolation(
                "q",
                "VALID_SEARCH",
                "must be 1 to ${SearchTerms.MAX_GRAPHEMES} characters, not only space, at most ${SearchTerms.MAX_OCTETS} bytes, with no NUL",
            )
    }
```

```kotlin
    /** A bond of [author] and [reader] with [DAYS] revealed days: the author's "zebra number N", the reader's "lion number N". */
    private fun history(
        author: UUID,
        reader: UUID,
    ): String {
        clock.set(BOND_CREATED)
        val bond = rig.bonds.pair(author, reader)
        (0 until DAYS).forEach { index ->
            clock.set(Instant.parse("${DAY_ONE.plusDays(index.toLong())}T10:00:00Z"))
            rig.bonds.submit(author, bond, "zebra number $index")
            rig.bonds.submit(reader, bond, "lion number $index")
        }
        clock.set(Instant.parse("${DAY_ONE.plusDays(DAYS.toLong())}T10:00:00Z"))
        return bond
    }

    /** Every page of [reader]'s search as sent, each UUID replaced by the order it first appears in the walk. */
    private fun normalised(
        reader: UUID,
        bond: String,
        asked: Map<String, String>,
    ): List<String> {
        val seen = LinkedHashMap<String, String>()
        return rig.pages(reader, bond, asked, route = "search").map { page ->
            UUID_PATTERN.replace(page.toString()) { found -> seen.getOrPut(found.value) { "id-${seen.size + 1}" } }
        }
    }

    private companion object {
        val LONG_AGO: Instant = Instant.parse("2019-12-31T10:00:00Z")
        val BOND_CREATED: Instant = Instant.parse("2026-09-13T10:00:00Z")
        val NOW: Instant = Instant.parse("2026-09-15T10:00:00Z")
        val DAY_ONE: LocalDate = LocalDate.of(2026, 9, 15)
        const val DAYS = 4
        const val DISPATCH_BUDGET = 10
        const val TIMEOUT_SECONDS = 10L
        val UUID_PATTERN = Regex("[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}")
        val WALKS =
            listOf(mapOf("q" to "lion", "limit" to "1"), mapOf("q" to "lion"), mapOf("q" to "zebra", "limit" to "1"), mapOf("q" to "number"))
    }
}
```

```kotlin
package com.moyi.contracts

import io.swagger.v3.oas.models.OpenAPI
import io.swagger.v3.oas.models.media.IntegerSchema
import io.swagger.v3.oas.models.media.StringSchema

private const val SEARCH_OPERATION = "search"

/** `gratitude.domain.SearchTerms.MAX_OCTETS`, internal to that module and mirrored here as the archive's bounds are. */
private const val SEARCH_MAX_OCTETS = 1024

/**
 * `GET /bonds/{bondId}/search` (ADR-0039). The handler takes `q`, `limit` and `cursor` as
 * optional text, read after the membership guard, so springdoc alone would document three
 * optional strings. This states what the route enforces: `q` required and bounded, and the
 * feed's own `limit` and `cursor`.
 *
 * In a file of its own: `OpenApiConfiguration.kt` sits at detekt's `TooManyFunctions` threshold.
 */
internal fun documentSearch(api: OpenAPI) {
    val operations =
        api.paths.values
            .flatMap { it.readOperations() }
            .filter { it.operationId == SEARCH_OPERATION }
    operations.forEach { it.description = SEARCH_DESCRIPTION }
    operations
        .flatMap { it.parameters.orEmpty() }
        .filter { it.`in` == "query" }
        .forEach { parameter ->
            when (parameter.name) {
                "q" -> {
                    parameter.required = true
                    parameter.schema = StringSchema().minLength(1).maxLength(SEARCH_MAX_OCTETS)
                    parameter.description =
                        "The words to look for: 1 to 100 characters (graphemes, counted on the NFKC-normalised, trimmed " +
                        "text), at most $SEARCH_MAX_OCTETS UTF-8 octets, not only space, no U+0000. `maxLength` states " +
                        "the octet cap in UTF-16 characters, a coarse hint. A value that cannot be searched is 422 " +
                        "VALIDATION_FAILED on `q`, and is never sent back. Words with no letter or digit in them " +
                        "(punctuation, emoji) match nothing."
                }

                "limit" -> {
                    parameter.schema =
                        IntegerSchema()
                            .minimum(DAYS_MIN_LIMIT.toBigDecimal())
                            .maximum(DAYS_MAX_LIMIT.toBigDecimal())
                            ._default(DAYS_DEFAULT_LIMIT)
                    parameter.description = "The most days to return, as on the feed. Only a null `nextCursor` means the end."
                }

                "cursor" -> {
                    parameter.schema = StringSchema().maxLength(DAYS_MAX_CURSOR_LENGTH)
                    parameter.description =
                        "The `nextCursor` of an earlier page of this search, unchanged. The feed's own cursor: a position, nothing else."
                }
            }
        }
}

private const val SEARCH_DESCRIPTION =
    "The days of the bond on which one entry the caller can read in full holds every word of `q`, newest first, each " +
        "day whole and in the feed's day shape. Whole words, compared without case or accents (`cafe` finds `Café`); " +
        "no prefixes, no stemming, no operators. The caller's own entry is found before it is revealed; the partner's " +
        "only once it has been.\n\n" +
        "**Only a null `nextCursor` means the end.** A page can hold fewer days than `limit` and still have a " +
        "`nextCursor`, because it is also bounded by its size. There is no count of matches, and nothing says which " +
        "entry of a day matched or where: a client that highlights does so itself.\n\n" +
        "`q` is never echoed in a refusal, and the response is never to be stored."
```

```kotlin
/**
 * NFR-033 ("no query whose cost grows with total table size rather than with the requested
 * page") and NFR-004 (search p95 ≤ 300 ms over 500k entries), asked of the search's own
 * statement (`ArchiveDays.matchingQuery`) as Postgres plans it (ADR-0039, the controller's
 * default 8). Not a test of the build: it seeds half a million rows. Run with
 * `MOYI_MEASURE=1 ./gradlew :modules:gratitude:test --tests "…SearchPlanMeasurement"`.
 *
 * One bond of two years, two entries a day (1,460 entries), and the rest of the table other
 * bonds of 500 entries each, at 100,000 rows and then at 500,000. Three words: one in every
 * entry (`thank`), one in an eighth (`lamp`), one in a single entry of the measured bond
 * (`zebra`). **The criterion:** no index scan in the plan returns more rows than the measured
 * bond has entries, at either size. A scan that returns more is reading other bonds' entries:
 * its cost grows with the table. And the warm execution time at 500k is under 300 ms.
 */
@SpringBootTest(classes = [GratitudeTestApplication::class])
@EnabledIfEnvironmentVariable(named = "MOYI_MEASURE", matches = "1")
internal class SearchPlanMeasurement(
    @Autowired dataSource: DataSource,
) : IntegrationTest() {
    private val jdbc = JdbcTemplate(dataSource)
    private val json = JsonMapper.builder().build()

    @AfterEach
    fun clear() {
        jdbc.execute("TRUNCATE TABLE entries, bond_days CASCADE")
    }

    @Test
    fun `a search reads in proportion to its bond, not to the table`() {
        jdbc.execute("TRUNCATE TABLE entries, bond_days CASCADE")
        seed(bonds = listOf(BOND), days = TARGET_DAYS)
        seed(bonds = List((SMALL - TARGET_DAYS * 2) / OTHER_ENTRIES) { UUID.randomUUID() }, days = OTHER_ENTRIES / 2)
        val small = measure()
        seed(bonds = List((LARGE - SMALL) / OTHER_ENTRIES) { UUID.randomUUID() }, days = OTHER_ENTRIES / 2)
        val large = measure()

        println("C6b SEARCH MEASUREMENT 100k: $small")
        println("C6b SEARCH MEASUREMENT 500k: $large")
        for ((size, measured) in listOf("100k" to small, "500k" to large)) {
            measured.forEach { (word, plan) ->
                withClue("$size, $word: $plan") { (plan.widestIndexScan <= TARGET_DAYS * 2) shouldBe true }
            }
        }
        large.forEach { (word, plan) -> withClue("500k, $word: $plan") { (plan.milliseconds < NFR_004_MS) shouldBe true } }
    }

    private data class Plan(
        val buffers: Long,
        val widestIndexScan: Double,
        val milliseconds: Double,
        val shape: String,
    )

    private fun measure(): Map<String, Plan> {
        jdbc.execute("ANALYZE entries")
        jdbc.execute("ANALYZE bond_days")
        return WORDS.associateWith { word ->
            val (sql, arguments) = ArchiveDays.matchingQuery(BOND, MEMBER, SearchTerms.of(word)!!, null, PAGE, emptySet())
            val explain = "EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON) $sql"
            val bind = PreparedStatementSetter { s -> arguments.forEachIndexed { i, v -> s.setObject(i + 1, v) } }
            // Twice first, so that what is measured is a warm run.
            repeat(2) { jdbc.query(explain, bind, RowCallbackHandler { }) }
            val text = jdbc.query(explain, bind, RowMapper { rs, _ -> rs.getString(1) }).single()
            val root = json.readTree(text)[0]
            val plan = root["Plan"]
            Plan(
                buffers = plan["Shared Hit Blocks"].asLong() + plan["Shared Read Blocks"].asLong(),
                widestIndexScan = indexScans(plan).maxOfOrNull { it["Actual Rows"].asDouble() } ?: 0.0,
                milliseconds = root["Execution Time"].asDouble(),
                shape = indexScans(plan).joinToString { "${it["Node Type"].asString()} on ${it["Index Name"]?.asString()}" },
            )
        }
    }

    private fun indexScans(node: JsonNode): List<JsonNode> =
        listOfNotNull(node.takeIf { it["Node Type"].asString().contains("Index") }) +
            node["Plans"]?.toList().orEmpty().flatMap(::indexScans)

    /** For each bond, [days] revealed days from 2024-01-01, two entries a day, every one holding `thank`. */
    private fun seed(
        bonds: List<UUID>,
        days: Int,
    ) {
        bonds.chunked(CHUNK).forEach { chunk ->
            jdbc.update(
                """
                WITH days AS (
                  INSERT INTO bond_days (id, bond_id, date, status, anchor_timezone, starts_at, ends_at, entry_count, created_at,
                                         closed_at, version)
                  SELECT gen_random_uuid(), b, date '2024-01-01' + i, 'REVEALED', 'UTC',
                         (date '2024-01-01' + i)::timestamptz, (date '2024-01-01' + i + 1)::timestamptz, 0,
                         (date '2024-01-01' + i)::timestamptz, (date '2024-01-01' + i + 1)::timestamptz, 0
                  FROM unnest(string_to_array(?, ',')::uuid[]) b, generate_series(0, ? - 1) i
                  RETURNING id, bond_id, date
                )
                INSERT INTO entries (id, bond_day_id, bond_id, author_member_id, text, text_search, status, created_at, intended_at,
                                     updated_at, revealed_at)
                SELECT gen_random_uuid(), d.id, d.bond_id, CASE WHEN s = 1 THEN ?::uuid ELSE gen_random_uuid() END, w, w, 'REVEALED',
                       now(), now(), now(), now()
                FROM days d, generate_series(1, 2) s,
                     LATERAL (SELECT 'thank you for the ' ||
                                     (ARRAY['lamp', 'walk', 'tea', 'rain', 'song', 'bread', 'map', 'hill'])[1 + abs(hashtext(d.id::text || s)) % 8] ||
                                     CASE WHEN d.bond_id = ?::uuid AND d.date = date '2024-06-01' AND s = 1 THEN ' and a zebra' ELSE '' END AS w) words
                """.trimIndent(),
                chunk.joinToString(","),
                days,
                MEMBER,
                BOND,
            )
        }
    }
```

```kotlin
     * `GET /bonds/{bondId}/on-this-day` (FR-092; ADR-0039): the days of earlier years dated the
     * bond's today, newest first, as the archive shows each.
     *
     * **Nothing, before anything is read, when the bond takes no writes from the caller**:
     * ended, left, blocked or counting down to deletion (the owner's Q-O3, decision 14). One
     * answer for every cause, so a block is not told from a leave.
     *
     * **Today is the bond's** (BR-3): [GetToday]'s own call, so both members are given the
     * same date and a memory changes at the bond's midnight.
     *
     * The candidates exclude days of tombstones and the known withdrawn ([ArchiveDays.onThisDay]);
     * the gate then reads every day, the marker last, and **a day is shown only if something on
     * it was read in full**: a withdrawal that commits after the candidates were read leaves its
     * author's days as tombstones, and those are not memories. Unpaginated: at most
     * [ArchiveDays.ON_THIS_DAY_YEARS] days, taken newest first while the text stays within
     * [textOctets] (the archive's bound, the first day always taken). Days past it are left out,
     * and are in the archive (decision 13).
     *
     * No opt-in is read: the owner's Q-O2 puts the opt-in on the weekly push (Phase 4), and
     * nothing of the partner's settings could reach this answer.
     */
    @Transactional(readOnly = true)
    fun onThisDay(
        membership: BondMembership,
        textOctets: Int = PAGE_TEXT_OCTETS,
    ): List<DayView> {
        if (!membership.takesWrites) return emptyList()
        val today = DayAssignment.dateFor(clock.instant(), null, membership.anchorTimeline.asCalendar()) { false }
        val candidates =
            archive.onThisDay(membership.bondId, membership.memberId, today, access.readerNow(membership).withdrawnAuthors)
        val read = read(membership, candidates).filter { it.readInFull.isNotEmpty() }
        val marked = marksOf(membership, read)
        val reacted = reactionsOn(read)
        val memories = Filling(ArchiveDays.ON_THIS_DAY_YEARS, textOctets)
        read.forEach { memories.offer(it, it.keptOf(marked), reacted) }
        return memories.days
    }
```
