# Slice C6a, the prompt library — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps
> use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET /bonds/{bondId}/today` carries the day's prompt, the same one for both
members and each in their own language, and `POST /bonds/{bondId}/entries` records which
prompt an entry answered.

**Architecture:** The prompt of the day is a pure domain function of the bond's id, the
bond-local date and the active library for the bond's audience: a per-bond permutation of
the eligible prompts, ordered by a stable hash, indexed by the date's epoch day. Nothing
anybody does is read, and nothing is recorded when a prompt is shown. The library is two
tables seeded by V24: `prompts` (id, audience, the `en` text, active) and `prompt_texts`
(per-locale text). The bond's type reaches `gratitude` through `bond.api.BondMembership`,
the caller's locale through `identity.api.UserSummary`.

**Tech Stack:** Kotlin, Spring Boot 4.1, Jackson 3 (`tools.jackson`), Postgres 18
(Testcontainers), `JdbcTemplate`, Flyway, Konsist, Kotest matchers, JUnit 5.

**Spec:** `docs/superpowers/specs/2026-09-28-the-daily-loop-design.md` §1 (the library is
Daniel's editorial work; C6 ships a seed), §5.1, §5.2, §7, §10, §11, §13. The C6 ledger

Not asked, defaults recorded as his: **Q-P3** (which prompt a revealed entry answered) is
not sent; **Q-P6** the seed's wording is placeholder, his editorial work.

**The controller's (2026-10-15; each is "the owner's to turn" in ADR-0038):**

1. Selection is a pure function of (bondId, bond-local date, active library for the
   audience): a per-bond permutation of the eligible prompts, ordered by a hash of
   bondId + promptId, indexed by the date's day number. No read of any member's activity,
   any entry or any impression. "Avoids recent repeats" means no repeat within one cycle.
2. **No `prompt_impressions` table.** V24 is prompts plus per-locale text. Spec §7 and doc 07
   are amended.
3. Locale per member: exact tag, then its language, then `en`. `locale` is added to
   `identity.api.UserSummary`.
4. Audience: CORE plus an overlay by bond type (COUPLE, FRIENDS, FAMILY; PARENT_CHILD gets
   FAMILY). `type` is added to `bond.api.BondMembership`.
5. Routes: `prompt: {id, text}` on `GET /today` only. `GET /prompts/daily` is not built
   (owed). `GET /prompts` is deferred (owner).
6. `prompt` is absent when the bond takes no writes (ended, blocked or read only, all
   alike), present whether or not the caller has written, and never depends on the partner.
7. `POST /entries` takes an optional `promptId`. An id that names no prompt is
   `422 VALIDATION_FAILED`. Not on `PATCH`. Never on a locked entry; not sent on a revealed
   one. `EraseEntry` nulls `prompt_id`.
8. No `used` flag.

## Decisions this plan makes (each goes into ADR-0038, apart from the rulings)

1. **The order is a plain SHA-256, not a keyed MAC.** The rank of a prompt in a bond's cycle
   is the first eight bytes, unsigned, of `SHA-256("moyi.prompt-order.v1" ‖ bondId ‖
   promptId)` (UUIDs as their sixteen big-endian bytes), ties broken by the prompt id. The
   one secret the codebase has, `moyi.security.hashing.secret` (`PersonalDataHasher`, the
   ETags' `HmacRepresentationDigest`), was considered and refused:
   - It is **EPHEMERAL in `local`**: a new value on every boot, so every bond's prompt would
     change on every restart of a developer's server, and of the smoke run's.
   - **Rotating it is a security act.** It would reshuffle every bond's prompt, mid-day, for
     both members at once; a security control would gain a product side effect that nobody
     rotating it would think of. `KnownAnswerTest` calls it "the three things made with the
     personal-data secret"; a fourth use that is not personal data dilutes that.
   - **Guessing the order harms nobody.** A bond id is known only to its two members (it is
     in their URLs); the library will be public once `GET /prompts` is built (doc 06:195);
     knowing tomorrow's prompt tells nobody anything about anybody. The order needs to be
     stable and spread, not secret.
   The label makes the hash this use's alone. A known-answer test pins it, because a change
   to the hash is a change to every bond's prompt on the day it deploys.
2. **The cycle is indexed by the date's epoch day**, `floorMod(date.toEpochDay(), n)`, not by
   days since `activeSince` (which is null for a bond still waiting for its second member).
   For a fixed library the sequence is periodic with period `n`, so no prompt repeats within
   *any* `n` consecutive days, not only within an aligned cycle. When the library changes
   (a deploy, Q-P4), `n` changes and the sequence is re-dealt from that day: a recent prompt
   can come back early, and **today's prompt can change mid-day for both members at once**.
   Accepted: the library changes by deploy only, and both members still agree.
3. **`prompt` is sent as `null`, not omitted**, when there is none. Every other optional
   field of this response (`myEntry`, `partnerEntry`) is a key with a `null` value, and the
   generated client models a nullable field, not a missing one. One `null` covers both
   causes (the bond takes no writes; the library has nothing for this bond), so nothing
   tells them apart, and nothing tells a block from a leave.
4. **Eligibility never depends on locale.** Every prompt has an `en` text, held on the
   `prompts` row itself (`NOT NULL`), so every prompt renders for every member and a
   translation, present or missing, never changes *which* prompt a bond gets. Translations
   live in `prompt_texts`, which refuses `en` so there is one `en` text.
5. **Locale matching is case-insensitive.** `users.locale` is stored as typed and
   `RegisterRequest` admits `PT-pt`. Candidates are the trimmed, lower-cased exact tag, its
   language subtag, then `en`, without duplicates. `prompt_texts.locale` is stored lower
   case and a `CHECK` holds that.
6. **The schema drops doc 07's `weight` and `category`.** Selection is unweighted (nothing
   specifies weights), and `category` is `audience` (`CORE`, `COUPLE`, `FRIENDS`, `FAMILY`).
   Doc 07's `prompts.locale` is replaced by `prompt_texts`.
7. **`entries.prompt_id` gains a foreign key to `prompts`** (`entries_prompt_fk`): both are
   this module's tables. Prompts are retired (`active = false`), never deleted.
8. **`promptId` may name any prompt in the table**: active or retired, any audience, today's
   or not. An offline draft (`states.md` §4, "Queued offline") posts the prompt it cached,
   which may since have been retired or may be yesterday's; refusing it would lose a
   person's words over a suggestion. The check is "names a prompt", nothing more.
9. **`promptId` is text on the wire, not a UUID.** A value that is not a UUID names no prompt
   either, and gets the one `422` an unknown id gets (field `promptId`, code
   `VALID_PROMPT`), decided after the bond's guard and after `BOND_ARCHIVED`. Typed as
   `UUID?`, a malformed value would be a `400` decided before the guard, a second answer for
   the same mistake. A JSON number or boolean is read as its text and refused the same way;
   an object or array is the standing `400`.
10. **`promptId` is never sent back**, on any shape and to anybody, its author included. The
    ruling covers the partner's locked and revealed shapes; one rule for every shape is
    simpler to hold, and no screen draws it (`tokens.md` §4 `EntryCard`).
11. **`PATCH /entries/{id}` ignores a `promptId` key**, as it ignores every key it does not
    know, and changes no `prompt_id`. A test pins that it changes nothing.
12. **Unknown keys on `POST /entries` stay ignored.** Run on 2026-10-15 at `cf8af00` (a
    throwaway MockMvc test, deleted): `{"text":"a","promptId":"<random uuid>"}` was `201`,
    and `{"text":"b","surprise":1}` and `{"text":"c","promptId":"not-a-uuid"}` both reached
    the service (they were `409 ENTRY_ALREADY_EXISTS`, not `400`). So today a client that
    sends `promptId` gets a silent success, and after this slice an unknown one is `422`.
    That is the point of the slice, and is in the ADR's Consequences. The route's general
    stance on unknown keys is not this slice's to change.
13. **`BondMembership.takesWrites` is added** (`isOpen && !hasLeft`) and used by the prompt.
    The three existing inline copies of that predicate (`SubmitEntry.kt:318`,
    `ChangeEntry.kt:96`, `ReactToEntry.kt:114`) are left as they are: thirteen state-map
    `codeRef`s quote those lines verbatim, and moving them is a refactor, not this slice.
    Recorded as owed.
14. **`bond.api.BondType` is a new public enum** mirroring the domain's four values, mapped
    exhaustively in `BondAccessAdapter`. PARENT_CHILD to FAMILY is the *prompt's* rule and
    lives in `gratitude` (`DailyPrompt.overlayOf`), not in `bond`.
15. **The prompt is computed from the membership the controller resolved**, before the
    joining-day reconcile, like the rest of `GetToday` (one calendar per request). A request
    that races an ending by milliseconds can still show a prompt. Nothing private is in a
    prompt, so this is accepted.
16. **A bond's type can change** (`PATCH /bonds/{id}`, `type`). When it does, today's overlay
    changes for both members at once. Accepted for the same reason as decision 2.
17. **The seed is 24 prompts, `en` only**: 12 CORE and 4 for each overlay. The wording is
    placeholder (Q-P6). A prompt's text is 1 to 200 characters, trimmed.
18. **An architecture rule pins what `DailyPrompt` may import**, so "reads no entry, no day,
    no mark, no reaction, no streak" is the build's to hold, not a reviewer's.
19. **`GET /today` gains three reads**: the library (about 24 rows today, 100 planned), the
    chosen prompt's texts, and the caller's user row. NFR-001 (p95 ≤ 150 ms) is not measured
    here; it is recorded as owed.

## Review focus

The five failure modes most likely to reach a person, each pinned by a test in the task
that owns the code:

1. **The partner's activity moves the prompt.** One member opening the app, writing,
   reading the reveal, marking, reacting, deleting, or being withdrawn from must not change
   one byte of the other's `prompt`, and both members must always see the same id.
   (Task 2, Step 6; Task 1, Step 3's member-free signature.)
2. **A member whose locale has no text.** `de`, `pt-BR` when only `pt-pt` exists, `PT-pt`,
   blank, or a user the directory no longer knows: the same prompt id as the partner, in
   the nearest text, `en` last, never an error and never no prompt. (Task 1, Step 5;
   Task 2, Step 7.)
3. **A bond that takes no writes.** Left, blocked (with and without withdrawal), counting
   down to deletion: `"prompt": null` for both members, the same bytes for a block as for a
   leave; a bond still waiting for its second member *does* get one. (Task 2, Step 8.)
4. **A library that shrinks or is empty for an audience.** No FAMILY prompts at all; the
   whole library retired; today's prompt retired mid-day: never a `500`, CORE alone where
   the overlay is empty, `null` where nothing is eligible, and both members still agree.
   (Task 1, Step 3; Task 2, Step 9.)
5. **The bond's own date chooses the prompt.** Across a DST change (Europe/London,
   2026-03-29) and a 45-minute offset (Asia/Kathmandu, +05:45), the prompt changes exactly
   at the bond's midnight, not UTC's, and two members are given the same one. (Task 2,
   Step 10.)

```kotlin
package com.moyi.gratitude.domain

import io.kotest.assertions.withClue
import io.kotest.matchers.collections.shouldContain
import io.kotest.matchers.collections.shouldContainExactlyInAnyOrder
import io.kotest.matchers.collections.shouldNotContain
import io.kotest.matchers.nulls.shouldBeNull
import io.kotest.matchers.shouldBe
import io.kotest.matchers.shouldNotBe
import org.junit.jupiter.api.Test
import java.time.LocalDate
import java.util.UUID
import kotlin.random.Random

/**
 * The prompt of the day (ADR-0038, controller ruling 1): a pure function of the bond, the
 * bond-local date and the library. Property-style, as `StreakPropertiesTest` is: seeded
 * randoms, so a failure is reproducible from the seed in its clue.
 *
 * What is NOT a parameter is half the point. There is no member, no entry, no day status
 * and no history in the signature: nothing anybody does can reach the answer (FR-064).
 */
internal class PromptOfTheDayTest {
    private fun id(n: Int) = PromptId(UUID.fromString("01990000-0000-7000-8000-%012x".format(n)))

    private fun library(
        random: Random,
        size: Int,
    ): List<LibraryPrompt> = List(size) { LibraryPrompt(id(it + 1), PromptAudience.entries[random.nextInt(PromptAudience.entries.size)]) }

    private fun eligible(
        library: List<LibraryPrompt>,
        overlay: PromptAudience,
    ) = library.filter { it.audience == PromptAudience.CORE || it.audience == overlay }.map { it.id }

    @Test
    fun `the same bond, date and library give the same prompt, whatever order the library is read in`() {
        repeat(200) { seed ->
            val random = Random(seed)
            val bond = UUID(random.nextLong(), random.nextLong())
            val lib = library(random, random.nextInt(1, 40))
            val date = LocalDate.of(2026, 1, 1).plusDays(random.nextLong(0, 2000))
            val overlay = PromptAudience.entries[random.nextInt(4)]
            withClue("seed $seed") {
                PromptOfTheDay.choose(bond, date, overlay, lib) shouldBe PromptOfTheDay.choose(bond, date, overlay, lib.shuffled(random))
            }
        }
    }

    @Test
    fun `no prompt comes back within any run of days as long as the cycle, and every eligible prompt comes once`() {
        repeat(200) { seed ->
            val random = Random(seed)
            val bond = UUID(random.nextLong(), random.nextLong())
            val lib = library(random, random.nextInt(1, 40))
            val overlay = PromptAudience.entries[random.nextInt(4)]
            val pool = eligible(lib, overlay)
            if (pool.isEmpty()) return@repeat
            // Any start, not one aligned with the cycle: the rule holds for every window.
            val start = LocalDate.of(2025, 6, 1).plusDays(random.nextLong(0, 3000))
            val run = (0 until pool.size).map { PromptOfTheDay.choose(bond, start.plusDays(it.toLong()), overlay, lib)!! }
            withClue("seed $seed") { run shouldContainExactlyInAnyOrder pool }
        }
    }

    @Test
    fun `only the shared core and the bond's own overlay are ever chosen, and an empty overlay leaves the core`() {
        repeat(200) { seed ->
            val random = Random(seed)
            val lib = library(random, random.nextInt(1, 40))
            val overlay = PromptAudience.entries[random.nextInt(1, 4)]
            val others = lib.filter { it.audience != PromptAudience.CORE && it.audience != overlay }.map { it.id }
            val bond = UUID(random.nextLong(), random.nextLong())
            (0L until 60L).forEach { day ->
                val chosen = PromptOfTheDay.choose(bond, LocalDate.of(2026, 3, 1).plusDays(day), overlay, lib)
                withClue("seed $seed day $day") { others shouldNotContain chosen }
            }
        }
        val coreOnly = listOf(LibraryPrompt(id(1), PromptAudience.CORE), LibraryPrompt(id(2), PromptAudience.COUPLE))
        PromptOfTheDay.cycle(UUID(1, 2), PromptAudience.FAMILY, coreOnly) shouldBe listOf(id(1))
    }

    @Test
    fun `an empty library, or one with nothing for this audience, is no prompt and not an error`() {
        PromptOfTheDay.choose(UUID(1, 2), LocalDate.of(2026, 10, 15), PromptAudience.COUPLE, emptyList()).shouldBeNull()
        PromptOfTheDay.choose(UUID(1, 2), LocalDate.of(2026, 10, 15), PromptAudience.COUPLE, listOf(LibraryPrompt(id(1), PromptAudience.FAMILY)))
            .shouldBeNull()
    }

    @Test
    fun `a library that shrinks still answers, and never with a prompt it no longer has`() {
        repeat(200) { seed ->
            val random = Random(seed)
            val lib = library(random, random.nextInt(2, 40))
            val kept = lib.filter { random.nextBoolean() }
            val bond = UUID(random.nextLong(), random.nextLong())
            val date = LocalDate.of(2026, 10, 15).plusDays(random.nextLong(0, 400))
            val overlay = PromptAudience.entries[random.nextInt(4)]
            val chosen = PromptOfTheDay.choose(bond, date, overlay, kept)
            withClue("seed $seed") {
                if (eligible(kept, overlay).isEmpty()) chosen.shouldBeNull() else eligible(kept, overlay) shouldContain chosen
            }
        }
    }

    @Test
    fun `two bonds are dealt the library in different orders`() {
        val lib = (1..12).map { LibraryPrompt(id(it), PromptAudience.CORE) }
        val orders = (1..50L).map { PromptOfTheDay.cycle(UUID(it, it), PromptAudience.COUPLE, lib) }.toSet()
        // Fifty bonds, twelve prompts: a rule that ignored the bond would deal one order to all of them.
        (orders.size > 40) shouldBe true
    }

    @Test
    fun `the order is a known answer, so a change to the hash is seen before it reshuffles every bond`() {
        // Computed independently (python3, hashlib.sha256 over the label and the two UUIDs' bytes,
        // first eight bytes unsigned big-endian; 2026-10-15 is epoch day 20741). The last-ranked
        // prompt's rank is 0xff5f72cd41f6f240: compared as a signed Long it would sort first.
        val bond = UUID.fromString("01990000-0000-7000-8000-0000000000b1")
        val lib =
            (1..7).map {
                LibraryPrompt(id(it), if (it <= 5) PromptAudience.CORE else if (it == 6) PromptAudience.COUPLE else PromptAudience.FRIENDS)
            }
        PromptOfTheDay.cycle(bond, PromptAudience.COUPLE, lib) shouldBe listOf(id(5), id(6), id(1), id(2), id(4), id(3))
        val week = (0L..6L).map { PromptOfTheDay.choose(bond, LocalDate.of(2026, 10, 15).plusDays(it), PromptAudience.COUPLE, lib) }
        week shouldBe listOf(id(3), id(5), id(6), id(1), id(2), id(4), id(3))
    }

    @Test
    fun `a prompt id is a canonical uuid, and nothing that merely parses as one`() {
        PromptId.parse("01990000-0000-7000-8000-000000000001") shouldBe id(1)
        // Upper-case hex is the same id (RFC 9562 reads it case-insensitively).
        PromptId.parse("01990000-0000-7000-8000-00000000000A") shouldBe id(10)
        PromptId.parse("1-1-1-1-1").shouldBeNull()
        PromptId.parse("not-a-uuid").shouldBeNull()
        PromptId.parse("").shouldBeNull()
        PromptId.parse("5").shouldBeNull()
        id(1) shouldNotBe id(2)
    }
}
```

```kotlin
package com.moyi.gratitude.domain

import java.nio.ByteBuffer
import java.security.MessageDigest
import java.time.LocalDate
import java.util.UUID

/**
 * Who a prompt is written for (cADR-0013): the core every bond shares, or one bond type's
 * overlay over it. `PARENT_CHILD` has no overlay of its own and is given FAMILY's
 * (`states.md` §2); that mapping is the service's, which knows bond types.
 */
internal enum class PromptAudience { CORE, COUPLE, FRIENDS, FAMILY }

/** A prompt as the choice sees it: which it is and who it is for. Never its words. */
internal data class LibraryPrompt(
    val id: PromptId,
    val audience: PromptAudience,
)

/**
 * Which prompt a bond is offered on a date (FR-047; ADR-0038, controller ruling 1).
 *
 * **A function of the bond, the date and the library, and of nothing else.** No member,
 * no entry, no day, no history and no record of what was shown: there is no parameter
 * that could carry one. So one member opening the app, writing or reading cannot move
 * what the other is offered (FR-064, T-09), both members are offered the same prompt
 * (the owner's Q-P1), and "recent" is computed, never recorded (ruling 2).
 *
 * **The cycle** is the prompts eligible for the bond (the core and the bond's overlay),
 * dealt into an order of the bond's own: each ranked by the first eight bytes, unsigned,
 * of `SHA-256(LABEL ‖ bondId ‖ promptId)`, ties by id. The date's epoch day indexes it,
 * modulo its length. For one library the sequence repeats with that period, so no
 * prompt comes back within any run of days as long as the cycle.
 *
 * **Not keyed.** The application's one secret would make the order change on every
 * local boot and on every rotation of a security control, and the order protects
 * nothing: knowing tomorrow's prompt tells nobody anything about anybody (ADR-0038,
 * decision 1). [LABEL] keeps the hash this use's alone.
 */
internal object PromptOfTheDay {
    /** The prompt of [date] for [bondId], or null when the library holds nothing for it. */
    fun choose(
        bondId: UUID,
        date: LocalDate,
        overlay: PromptAudience,
        library: Collection<LibraryPrompt>,
    ): PromptId? {
        val cycle = cycle(bondId, overlay, library)
        if (cycle.isEmpty()) return null
        return cycle[Math.floorMod(date.toEpochDay(), cycle.size.toLong()).toInt()]
    }

    /** The bond's order of its eligible prompts, whatever order [library] arrived in. */
    fun cycle(
        bondId: UUID,
        overlay: PromptAudience,
        library: Collection<LibraryPrompt>,
    ): List<PromptId> {
        val eligible =
            library
                .filter { it.audience == PromptAudience.CORE || it.audience == overlay }
                .map { it.id }
                .distinct()
        val ranks = eligible.associateWith { rank(bondId, it) }
        return eligible.sortedWith(compareBy<PromptId> { ranks.getValue(it) }.thenBy { it.value })
    }

    private fun rank(
        bondId: UUID,
        promptId: PromptId,
    ): ULong {
        val digest = MessageDigest.getInstance("SHA-256")
        digest.update(LABEL)
        digest.update(bytesOf(bondId))
        digest.update(bytesOf(promptId.value))
        return ByteBuffer.wrap(digest.digest()).long.toULong()
    }

    private fun bytesOf(id: UUID): ByteArray =
        ByteBuffer
            .allocate(UUID_BYTES)
            .putLong(id.mostSignificantBits)
            .putLong(id.leastSignificantBits)
            .array()

    private const val UUID_BYTES = 16
    private val LABEL = "moyi.prompt-order.v1".toByteArray(Charsets.UTF_8)
}
```

```kotlin
 * changed by migration (the owner's Q-P4).
```

```kotlin
 *
 * **Which prompt** is [PromptOfTheDay]'s, from the bond, the date and the library alone.
 * **Its words** are the caller's own locale's, from their own stored locale; the partner's

@Service
internal class DailyPrompt(
    private val library: PromptLibrary,
    private val users: UserDirectory,
) {
    fun on(
        membership: BondMembership,
        date: LocalDate,
    ): PromptView? {
        if (!membership.takesWrites) return null
        val id = PromptOfTheDay.choose(membership.bondId, date, overlayOf(membership.type), library.active()) ?: return null
        val locales = PromptLocale.candidates(users.find(membership.userId)?.locale)
        // `prompts.text` is the `en` text and NOT NULL, and `en` ends every candidate list.
        val text = checkNotNull(PromptLocale.textIn(locales, library.textsOf(id))) { "prompt ${id.value} has no en text" }
        return PromptView(id, text)
    }

    companion object {
        /** The overlay a bond's type is offered (cADR-0013; `states.md` §2: one card covers parent, child and sibling). */
        fun overlayOf(type: BondType): PromptAudience =
            when (type) {
                BondType.COUPLE -> PromptAudience.COUPLE
                BondType.FRIENDS -> PromptAudience.FRIENDS
                BondType.FAMILY, BondType.PARENT_CHILD -> PromptAudience.FAMILY
            }
```
